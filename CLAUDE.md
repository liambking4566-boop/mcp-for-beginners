# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

**MCP for Beginners** is Microsoft's open-source curriculum for learning the Model Context Protocol (MCP). It is primarily a documentation repository (11 sequential modules, `00-` through `11-`), with runnable sample/solution code embedded throughout in C#, Java, JavaScript, TypeScript, Python, and Rust. The curriculum currently targets **MCP Specification 2026-07-28** (see `01-CoreConcepts/mcp-2026-07-28.md` for what changed from `2025-11-25`); some hands-on examples remain pinned to the older spec version until SDKs catch up — don't "fix" version mismatches without checking which spec a given lesson intentionally targets.

An `AGENTS.md` file at the repo root also documents this repository in detail (setup commands, an "MCP 7-28 Readiness" checklist, contribution rules); treat it as authoritative alongside this file — it is kept in sync and not duplicated here.

## Commands

There is no root build. Validation happens per-area:

```bash
# Markdown lint (whole repo, excluding generated content)
npx --yes markdownlint-cli2 "**/*.md" "#node_modules" "#translations" "#translated_images"

# Markdown link pattern audit
find . -name "*.md" -not -path "*/node_modules/*" -not -path "./translations/*" -not -path "./translated_images/*" -print0 | xargs -0 grep -En "\[.*\]\(.*\)"

# TypeScript sample
cd 03-GettingStarted/samples/typescript && npm ci && npm test && npm run build

# Python sample (example: AI Toolkit lab)
cd 10-StreamliningAIWorkflowsBuildingAnMCPServerWithAIToolkit/lab3/code/weather_mcp && python -m pip install -e . && pytest -q

# Java sample
cd 03-GettingStarted/samples/java/calculator && mvn -B -ntp test verify
```

For any other sample/solution directory, look for its own README/setup instructions — each is a self-contained project (`npm install && npm start`, `pip install -r requirements.txt`, `mvn spring-boot:run`, etc.) and is not wired into a repo-wide build or test runner.

## Architecture

- **Module directories (`00-…` through `11-…`)**: the curriculum, meant to be read/followed in numeric order. Each module is a self-contained unit with its own `README.md` and, where relevant, `samples/` (per-language exercises) and `solution/` (completed reference implementations) subfolders — this pattern repeats independently inside many lesson subfolders rather than at the module root (e.g. `03-GettingStarted/01-first-server/solution/<language>/`).
- **`11-MCPServerHandsOnLabs/`**: a distinct, longer sequence of labs (00-Introduction through 12-Best-Practices) building one database-integrated MCP server end-to-end (Postgres + pgvector, Azure Container Apps/OpenAI/Content Safety/Application Insights), separate from the numbered top-level modules.
- **`translations/` and `translated_images/`**: auto-generated by the `co-op-translator` GitHub Action from the English markdown/images on every push to `main`. **Never hand-edit files under these directories** — edits will be overwritten and PRs touching them will fail translation checks. Only edit the English source files in the module directories and `images/`.
- **`images/`**: source diagrams/screenshots referenced by the English docs; localized copies live under `translated_images/`.
- **`changelog.md`**: log of significant repository changes. **`study_guide.md`**: curriculum navigation aid.

## Working Conventions

- Edit only English markdown in the numbered module directories — translation is fully automated downstream.
- Each sample/solution folder is independently versioned per language; don't assume shared dependencies or a monorepo-style workspace across them.
- When adding or modifying a hands-on example, check whether the surrounding lesson text specifies an MCP spec version (`2026-07-28` vs. the older `2025-11-25`) and keep code consistent with that lesson's stated target.
